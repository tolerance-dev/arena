# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Prototype mode — read first

The product concept is still changing week to week (tasks, judging, scoring may all be redone). The goal is a
working skeleton, fast. This section overrides any skills and default habits:

- **Write code directly.** No brainstorming sessions, no specs or task-by-task plans in `docs/`, no
  subagent-driven-development, no TDD, no per-task or whole-branch reviews — unless the user asks for one. If a
  change needs a plan, a short list of steps in chat is enough.
- **No new tests**, except for a bug in the gateway's token metering or the run verdict (`internal/gateway`,
  `internal/runs`).
- **"Done" = it compiles and works locally**: `make test-fast`, then `make dev` (or `make up`) and the flow
  clicked through. Full `make test` is optional. CI (`ci.yml`) is manual-only; nothing runs on push.
- **Don't overload, don't copy "how everyone does it".** Each page and each brief shows only what it is for, and
  nothing another page already shows (no stats rows, duplicate leaderboards, side panels, "how it works" filler
  added by default). Build the minimum that serves the point, then extend one thing at a time when there is a reason.
  When in doubt, leave it out and ask.
- **Throwing code away is fine.** When the concept changes, delete the old feature (code, routes, pages, tests)
  rather than keeping it compatible.
- **Never deploy yourself, no ops work unless asked.** Don't run `gh workflow run deploy` and don't change prod by
  any other path: no SSH changes on the server, no Cloudflare changes, no workflows that do either — even when
  asked to "do everything". Prepare the PR, then tell the user what to press (Actions → deploy → Run workflow), with
  which inputs (`ref=<sha>` rolls back, `reset_db=true` wipes the DB — needed after any schema change), and what has
  to be set up by hand first. Server details: `deploy/README.md`.
- **Docs**: `README.md` is a short pitch + how to run; there are no specs. Update this file only with what would
  trip up the next session.
- **Git: only through pull requests.** Pushing to `main` is blocked (branch protection, admins included). Work on a
  branch (`git fetch && git checkout -b <name> origin/main`), push it, open a PR with `gh pr create` and stop
  there: **never merge a PR yourself** (no `gh pr merge`, no auto-merge). Give the PR link in the reply. Never try
  to push to `main` or weaken the protection.

## What this is

**tolerance** (https://tolerance.cc; env vars are `ARENA_*`, the database is `arena`): an **agent arena for whole
apps**. An admin uploads an agent (a `run.sh` or a zip with `run.sh`) plus its LLM key; a run puts the agent in a
sandbox with a task (`TASK.md` + shared mock data); the agent writes backend and frontend; the platform measures
and judges the result. Older features were deleted; they are in git history (before "Pivot to agent runs").

Run lifecycle (`internal/runs/worker.go`), status `queued → agent → checking → done | infra_error`:
1. **agent**: container from `arena-runtime:1` on the internal Docker network `arena-agents` (no route out).
   `/agent` = the bundle, `/work` = `TASK.md` + `data/`. LLM base URLs point at the gateway, `*_API_KEY` is a
   per-run token (`gateway_tokens`). Killed on time limit, budget or cancel, then `docker commit` →
   `arena-run:<hex>` (the snapshot; previews and checks start from it).
2. **checking**: LOC + `source_zip` from the snapshot, then a check container runs `internal/runs/verify.py` as
   root; it starts `/work/start.sh` as uid 1001 (so the app can't read `/verify`), runs the checks, screenshots
   desktop/mobile and runs the judge (Anthropic SDK through the gateway, ends with `submit_verdict`).
3. **score** = 0 if the app didn't start, else 30% checks + 70% judge (checks only when no judge). No task has a
   `judge.md` yet → judge off (`judge.status = "off"`; the code stays for later).

`cmd/gateway` (a container on `default` + `arena-agents`, alias `gateway`): `/anthropic/*`, `/openai/*` swap the
run token for the real key (agent keys sealed with `ARENA_SECRET_KEY`; the judge key `ARENA_JUDGE_API_KEY` lives on
the gateway only), meter usage from JSON/SSE into `runs.tokens_*`, enforce budget; `/npm/*`, `/pypi/*`,
`/pyfiles/*` are read-only registry mirrors. Port 8091 serves live previews:
`http://<run-hex>.preview.localhost:$GATEWAY_PORT` starts `arena-preview-<hex>` from the snapshot on demand.
`ARENA_GATEWAY_FAKE=true` answers LLM calls locally (fake judge included) to click through without keys.

Tasks are whole products (`marketplace`, `hotels`, `cinema`) in `backend/internal/tasks/catalog/<slug>/`:
`TASK.md` (a short product brief, no API contract; the site shows only its product part, see `siteBrief`), optional
`judge.md` (overridable from `ARENA_TASKS_HIDDEN_DIR/<slug>/judge.md`), and `task.json` + `data/*.json` GENERATED by
`internal/tasks/gen_data.py` — edit titles, limits and `ui_text` there and rerun it. `catalog/RULES.md` is appended
to the brief the agent gets. There are no API checks (`checks: []`): with `"ui": true` verify.py checks the app
starts, `/` serves HTML and shows `ui_text` (seed data, HTML or SVG text, case-insensitive). The data has no image
URLs (no internet in the sandbox). The task page's check list comes from `Task.CheckNames()`; keep it in step with
verify.py's check names. Example agents: `examples/agents/{claude-code,demo}`; `demo` writes a plain storefront
that passes every check.

Prod previews are agent code on a sibling subdomain (`p-<hex>.tolerance.cc`), so the api refuses cross-origin
writes (`sameOrigin` in `cmd/api/handler.go`) and the session cookie is `__Host-arena_session` in prod: keep both.

Monorepo: `backend/` (Go module `tolerance`) and `frontend/` (Next.js, talks to the backend over HTTP only).

## Commands

```sh
make dev         # postgres + gateway in Docker, migrate, then api and web natively (Ctrl-C stops api/web)
make up          # whole stack in Docker
make down        # make reset also wipes the DB volume
make images      # arena-runtime:1 (sandbox image), built only when missing
make gateway     # rebuild + restart the gateway container (after Go changes in internal/gateway)
make test-fast   # gofmt + go vet + go test + pnpm typecheck
```

The api refuses to start without GitHub or Google OAuth keys. Locally they live once in `~/.config/tolerance/env`
(the Makefile loads it before `.env`). Ports come from `.env` (`WEB_PORT`, `API_PORT`, `PG_PORT`, `GATEWAY_PORT`).
Admins (upload agents, start runs) are `ownerEmail` (in `cmd/api/config.go`) + `ARENA_ADMIN_EMAILS`, locally too:
the dev login does NOT make everyone an admin; dev-sign in as the owner to upload. Others see `/admin` disabled.

## Rules that stay even in prototype mode

- **Sandbox safety**: agent/check/preview containers run with dropped caps on the internal `arena-agents`
  network; the real LLM keys never enter a sandbox; the app under check runs as uid 1001, away from `/verify`.
- `infra_error` is the platform's fault, never a score.
- **Database: no data worth keeping yet** (prod included): edit `backend/migrations/00002_schema.sql` in place and
  recreate the DB (`make reset` locally, `reset_db=true` on prod) instead of adding migrations or writing
  compatibility/cleanup code.
- Agent-written logs are sanitized server-side (`internal/platform/sanitize`).
- Run snapshots (`arena-run:*` images) older than a day are removed hourly by the worker, except each agent's
  best run per task.
- Errors go through `httpx.WriteError` (`{code, message, request_id}`); timestamps are UTC (`.UTC()` after
  scanning — pgx returns local time).
- Frontend: no mocks, data from the API, browser calls same-origin `/api/v1/*`.
- UI copy is bilingual (en, ru): strings live in `frontend/lib/i18n/messages/<area>.ts` (`defineMessages`, ru must
  have every en key), read with `useT(m)` in client components or `await getT(m)` on the server; dates via
  `formatDate`/`formatDateTime` from `lib/i18n/core`. Language = `lang` cookie, else Accept-Language, else en.
  Task content (TASK.md, judge.md) stays English.
- Colours are tokens from `frontend/app/globals.css`, never raw hex in classes: `bg-terminal`/
  `text-terminal-foreground` for copy blocks and dark panels (navy in both themes), `border-input` for control
  borders (3:1), `border-strong` for dashed empty states.
- Commit subjects in English, imperative, sentence case, no `feat:` prefixes. README is in Russian, code and
  comments in English.
